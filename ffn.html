2.FFN压缩在做什么？

项目里的FFN 通道压缩本质上是一个受控结构实验，不是完整的模型训练或模型部署方案。它把 SVD UNet 内部 FFN 的某些全连接层改窄，然后比较 Baseline 和 Treatment 的 FLOPs、访存下界与算术强度，观察 Roofline 瓶颈是否迁移。

*这里的 SVD 指 Stable Video Diffusion，不是“对权重做奇异值分解”。

2.1. 项目现在具体在改什么？

设原 FFN 中有一个线性层：

[ Y=XW^\top+b,\qquad X\in\mathbb R^{d{in}}, W\in\mathbb R^{d{out}\times d_{in}} ]

项目文档定义的 Treatment 是把它换成一个中间通道更窄的两层结构：

[ h=\max(1,\operatorname{int}(r,d{out})),\qquad r=0.5 ][ H=XW{\text{down}}^\top ][ Y'=HW_{\text{up}}^\top+b ]

其中：

  • down：把输入压到 h 个通道；
  • up：再把 h 个通道恢复到原来的 d_out；
  • 输入、输出维度不变，因此模型前后模块不需要改 shape；
  • 只替换 FFN 内部目标 Linear；
  • 不替换 to_q/to_k/to_v/to_out；
  • 默认不在 Bottleneck 内部额外加激活函数，原来 FFN 的 GELU/GEGLU 仍留在原位置。

2.2. 一个必须注意的数学问题

r=0.5 不一定等于参数量和 FLOPs 减少 50%。

原 Linear 权重参数量约为：

[ P0=d{in}d_{out} ]

Bottleneck 后：

[ P1=d{in}h+h,d_{out} ]

例如：

原 Linear r=0.5 后 hidden 参数量变化
1024→1024 512 约不变
1024→4096 2048 增加到约 2.5 倍
4096→1024 512 约减少 62.5%

尤其 GEGLU 的投影层常见输出维度是 2 × d_ff。如果盲目对每个 Linear 的 out_features 应用 0.5，可能把原本的扩张层变成两层更宽的层，反而增加计算。

3. 推荐的实际实现流程

第一步：跑通 Baseline

冻结模型、权重、输入 shape、FP16、batch、帧数和随机种子。通过 hook 打印：

for name, module in unet.named_modules():
    if isinstance(module, torch.nn.Linear):
        print(
            name,
            module.in_features,
            module.out_features,
            module.weight.numel()
        )

重点记录：

  • 哪些 Linear 属于 FFN；
  • 哪些是 to_q/to_k/to_v/to_out；
  • FFN 的激活函数在哪里；
  • 每个目标 Linear 是扩张层还是收缩层；
  • FFN FLOPs 占 UNet 总 FLOPs 的比例。

项目规定，FFN 占比低于 15% 时，需要把注意力投影并入“通道压缩模块”，并相应修改 RQ 表述，不能继续把全部结果称为“纯 FFN”。

第二步：实现可审计的 Bottleneck Linear

如果严格按当前任务卡的定义，可以使用：

import torch
from torch import nn


class BottleneckLinear(nn.Module):
    def __init__(self, original: nn.Linear, r: float = 0.5):
        super().__init__()
        d_in = original.in_features
        d_out = original.out_features
        h = max(int(d_out * r), 1)

        # 不额外添加非线性，原来 FFN 的 GELU/GEGLU 保持原位置
        self.down = nn.Linear(d_in, h, bias=False)
        self.up = nn.Linear(h, d_out, bias=original.bias is not None)

        if original.bias is not None:
            with torch.no_grad():
                self.up.bias.copy_(original.bias)

        self.in_features = d_in
        self.out_features = d_out
        self.hidden = h

    def forward(self, x):
        return self.up(self.down(x))

替换时只处理已经审计过的 FFN 前缀：

def replace_selected_linears(parent, prefix, should_replace, r=0.5):
    for child_name, child in list(parent.named_children()):
        full_name = f"{prefix}.{child_name}" if prefix else child_name

        if isinstance(child, nn.Linear) and should_replace(full_name):
            setattr(parent, child_name, BottleneckLinear(child, r))
        else:
            replace_selected_linears(
                child, full_name, should_replace, r
            )

不要使用范围过宽的规则，例如只判断 "ff" in name。应明确保存：

{
  "replaced": [
    "temporal_transformer.blocks.0.ff.net.0.proj",
    "temporal_transformer.blocks.0.ff.net.2"
  ],
  "skipped": [
    "temporal_transformer.blocks.0.attn1.to_q",
    "temporal_transformer.blocks.0.attn1.to_k",
    "temporal_transformer.blocks.0.attn1.to_v",
    "temporal_transformer.blocks.0.attn1.to_out"
  ]
}

第三步：做单变量验收

Treatment 必须满足：

  • 输出 shape、dtype、device 与 Baseline 一致；
  • 输入、batch、帧数、分辨率完全相同；
  • 只替换目标 FFN Linear；
  • 未被替换模块的权重哈希不变；
  • 不额外增加激活、Dropout 或量化；
  • 用同一套 hook 统计整体、FFN、attention 和卷积；
  • 记录替换前后的参数量、FLOPs 和访存下界。

建议同时计算每个目标层的：

[ P{\text{ratio}}= \frac{d{in}h+h d{out}}{d{in}d{out}} ][ F{\text{ratio}}= \frac{d{in}h+h d{out}}{d{in}d{out}} ]

如果某个层替换后 P_ratio > 1，就要在 ffn_decision.md 中明确说明，不能把它写成“压缩”。

第四步：测量并解释

按照项目要求执行：

Baseline → Treatment → Baseline 复核

主要比较：

  • 整体、FFN、attention、卷积 FLOPs；
  • 权重访存和激活访存下界；
  • 算术强度 (I=\mathrm{FLOPs}/\mathrm{Bytes})；
  • (q=I/I^*)，判断 compute-bound 还是 memory-bound；
  • Roofline 图上 Baseline 到 Treatment 的箭头方向；
  • 边缘设备额外记录 VDD_IN 和 FLOP/J。

跨云 GPU 和 Jetson 时，只比较变化方向，不要直接比较绝对 FLOPs 或算术强度。
